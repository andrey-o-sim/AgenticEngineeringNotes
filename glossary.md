# Glossary

## Токены и представление текста

### Tokenizer

Компонент, который преобразует исходный текст в последовательность токенов и token IDs по правилам конкретного vocabulary.

### Token

Дискретная текстовая единица после токенизации: слово, часть слова, знак пунктуации, пробел или другой фрагмент.

### Token ID

Числовой идентификатор токена в vocabulary конкретного tokenizer.

### Vocabulary

Фиксированный набор токенов, которым tokenizer сопоставляет token IDs.

### Subword tokenization

Подход, при котором частые последовательности могут быть крупными токенами, а редкие слова разбиваются на несколько частей.

### BPE

Один из алгоритмов subword tokenization, объединяющий часто встречающиеся соседние последовательности.

### Embedding

Числовой вектор, получаемый из token ID и используемый нейросетью для дальнейших вычислений.

### Detokenization / tokenizer decoding

Обратное преобразование token IDs в байты/текст. Это не decode phase LLM inference.

## Inference и генерация

### Inference

Запуск уже обученной модели для обработки конкретного input и получения output. Во время обычного inference веса модели не переобучаются.

### Prefill

Фаза inference, в которой обрабатываются заранее известные input tokens и формируется состояние/KV cache.

### Decode phase

Последовательная autoregressive генерация новых output tokens после prefill.

### Generation

Процесс выбора и добавления следующих токенов до завершения ответа или достижения stop/output limit.

### Logits

Не-нормализованные оценки модели для возможных следующих токенов.

### KV cache

Кэш key/value представлений attention для уже обработанного prefix.

### Thinking tokens

Внутренние reasoning tokens, используемые reasoning-моделью и учитываемые в output billing.

### Effort
Параметр новых Claude для управления глубиной thinking/reasoning и связанным token spend. В Claude Sonnet 5 adaptive thinking включён по умолчанию, а `effort` управляет его глубиной.

`effort` не является прямой заменой `temperature`, `top_p` или `top_k`: sampling-параметры управляли выбором токенов, а `effort` управляет объёмом reasoning.

## Обучение и знания модели

### Веса модели (Model weights / Parameters)

Обучаемые числовые параметры нейросети. Во время обучения они обновляются, чтобы уменьшать ошибку предсказаний; во время обычного inference выпущенного snapshot считаются фиксированными.

### Pretraining / Предобучение

Базовый этап обучения языковой модели на большом корпусе данных, где модель учится предсказывать следующий токен и формирует общие языковые способности и обучающие знания в весах.

### Loss

Числовая функция ошибки, показывающая, насколько предсказание модели отличается от целевого результата. Обучение стремится уменьшать loss.

### Backpropagation

Алгоритм обратного распространения ошибки, вычисляющий градиенты параметров по loss, чтобы оптимизатор мог обновить веса в направлении уменьшения ошибки.

### MLP

Feed-forward часть Transformer-блока, выполняющая нелинейное преобразование представлений. Значительная часть параметров многих Transformer-моделей находится в MLP-блоках; знания при этом распределены по всей сети, а не хранятся в одном отдельном модуле.

### Unembedding / Output projection

Преобразование скрытого представления модели в logits по vocabulary, из которых затем получается распределение вероятностей следующего токена.

### Post-training

Дополнительные этапы обучения после pretraining, формирующие поведение ассистента: следование инструкциям, предпочтения, безопасность, стиль взаимодействия и другие целевые свойства.

### SFT

Supervised Fine-Tuning — дообучение на размеченных примерах желаемых запросов и ответов. Помогает превратить базовую next-token модель в модель, устойчиво следующую формату инструкций и диалога.

### RLHF

Reinforcement Learning from Human Feedback — обучение по человеческим предпочтениям, где люди сравнивают или ранжируют ответы, а полученный сигнал используется для дальнейшей настройки поведения модели.

### Reward model

Модель предпочтений, обученная предсказывать человеческую оценку вариантов ответа и выдавать числовой reward, который может использоваться при RLHF.

### Constitutional AI

Подход Anthropic к обучению поведения модели на основе набора принципов: модель критикует и исправляет ответы относительно этих принципов, а затем предпочтения могут использоваться в дальнейшей настройке.

### RLAIF

Reinforcement Learning from AI Feedback — reinforcement learning, где часть preference-сигнала формируется оценками другой модели, например на основе принципов Constitutional AI.

### Snapshot модели

Зафиксированная выпущенная версия модели с определённым набором весов. Обычные запросы к такому snapshot не переписывают его параметры.

### Frozen weights / Зафиксированные веса

Состояние, при котором параметры выпущенной модели не изменяются во время обычного inference. Новые данные могут влиять на ответ через контекст, но не записываются автоматически в веса.

### Knowledge cutoff

Граница периода, после которого нельзя считать встроенные обучающие знания модели полными и надёжными. Для конкретных моделей дата cutoff различается.

### Reliable knowledge cutoff

Дата, до которой знания модели считаются наиболее полными и надёжными. Это более консервативная граница, чем training data cutoff.

### Training data cutoff

Более широкая граница данных, которые могли использоваться при обучении. Между reliable cutoff и training cutoff модель может знать отдельные факты, но надёжность ниже.

### Обучающие знания (Training knowledge)

Общие знания и способности, сформированные во время обучения и закодированные в параметрах модели. Для изменения таких знаний нужен новый цикл обучения или дообучения.

### Контекстные знания (Contextual knowledge)

Информация, предоставленная модели во время конкретного inference через prompt, файлы, историю, результаты поиска или инструменты. Она может быть обновлена непосредственно перед запросом без изменения весов.

### Серая зона cutoff

Период между reliable knowledge cutoff и training data cutoff, где отдельные данные могли попасть в обучение, но их полнота и надёжность ниже, чем до reliable cutoff.

## Attention и Transformer

### Contextual representation

Контекстуализированное представление — вектор токена после обработки Transformer с учётом окружающих токенов. В отличие от исходного embedding, оно зависит от конкретного контекста.

### Attention

Механизм, который вычисляет, какие доступные позиции последовательности релевантны текущей позиции, и формирует новое представление как взвешенную комбинацию передаваемой информации.

### Self-attention

Вариант attention, в котором Query, Key и Value строятся из представлений одной и той же последовательности. Он позволяет токенам учитывать другие токены текущего контекста.

### Query (Q)

Вектор, описывающий, какую информацию текущая позиция ищет у других доступных позиций.

### Key (K)

Вектор с признаками позиции, по которым определяется её релевантность для конкретного Query.

### Value (V)

Вектор с информацией позиции, которая передаётся в новое представление пропорционально вычисленному attention weight.

### Attention score

Числовая оценка совместимости Query и Key до softmax. В scaled dot-product attention она получается из скалярного произведения `QKᵀ` с последующим масштабированием.

### Attention weight

Нормализованный через softmax вес, определяющий вклад соответствующего Value-вектора в новое представление. Для одного Query сумма attention weights по доступным позициям равна `1`.

### Scaled dot-product attention

Стандартная форма attention:

```text
Attention(Q, K, V) = softmax(QKᵀ / √d_k) V
```

Совместимость Query и Key определяет веса, после чего с этими весами смешиваются Value-векторы.

### d_model

Размерность основного скрытого представления токена в Transformer. В multi-head attention это пространство обычно разделяется между несколькими heads.

### d_k

Размерность Key и Query внутри одного attention head. В формуле scaled dot-product attention используется множитель `1 / √d_k`, чтобы контролировать масштаб attention scores.

### Causal mask

Маска в autoregressive decoder-only LLM, запрещающая текущей позиции учитывать будущие токены. Позиция может использовать только уже доступный префикс.

### Attention head

Один независимый набор обучаемых проекций Query, Key и Value, создающий собственную систему attention weights и собственное представление связей между позициями.

### Multi-head attention

Механизм, в котором несколько attention heads работают параллельно с разными обучаемыми проекциями. Их результаты объединяются и проходят выходную проекцию.

### Full attention

Вариант self-attention, где каждая допустимая позиция может сравниваться со всеми другими допустимыми позициями. Матрица `QKᵀ` для последовательности длины `n` имеет размер `n × n`.

### Квадратичная сложность full attention

Рост числа попарных attention scores пропорционально `n²`, где `n` — длина последовательности. Увеличение длины контекста в 10 раз увеличивает число таких сравнений примерно в 100 раз.

### Attention dilution

Полезная инженерная интуиция: по мере роста контекста больше позиций конкурируют за вклад в новое представление. Это не означает равномерный вес `1/n` и не гарантирует ухудшение каждого токена, но важный сигнал может становиться менее заметным среди большого количества кандидатов.

### Effective context

Практически полезная часть контекста, которую модель способна надёжно использовать для конкретной задачи. Номинальный context window описывает вместимость, а effective context — реальную надёжность использования информации.

### External scratchpad

Явно сформированный промежуточный рабочий блок с фактами, решениями, ссылками или результатами инструментов. Он хранится вне скрытого reasoning модели и используется для уменьшения шума и проверки промежуточного состояния.

### Focused pass

Отдельный проход по узкой части большой задачи: например, анализ одного файла или логической группы файлов. Цель — уменьшить объём нерелевантного контекста и получить структурированный промежуточный результат.

### Integration pass

Финальный проход, который объединяет результаты нескольких focused passes и проверяет связи между ними, например cross-file контракты, изменённые сигнатуры и общие инварианты.

## Контекст и память

### Context

Информация, доступная модели в текущем inference.

### Context window

Максимальный токенный объём активного контекста, поддерживаемый моделью/API.

### Context rot

Практическая деградация способности надёжно использовать нужную информацию по мере роста/зашумления context.

### Lost in the Middle

Эффект, при котором информация в середине очень длинного context может извлекаться хуже, чем ближе к началу или концу.

### MRCR

Long-context benchmark для поиска и различения нескольких похожих фрагментов информации.

### Mean Match Ratio

Метрика MRCR: средняя степень совпадения ответа модели с целевым фрагментом; это не обычная accuracy полностью правильных ответов.

### Compaction

Сжатие длинной conversation history в более короткое рабочее представление. Это lossy compression: ключевое состояние сохраняется, но отдельные детали могут исчезнуть.

### /compact

Команда Claude Code для compaction текущей conversation history: длинная история заменяется более коротким summary, чтобы освободить context window и продолжить ту же задачу.

### /clear

Команда Claude Code для очистки текущей conversation history перед новой независимой задачей. Она не удаляет внешние persistent-файлы или знания из весов модели.

### External state

Состояние вне активного context window: файлы, Git, БД, object storage, memory-файлы и другие persistent storage, из которых нужные данные можно снова загрузить в context.

### Stateless / Stateless API

Архитектурный контракт, при котором независимый запрос не получает предыдущую conversation history автоматически. Нужное состояние должно быть снова передано в запросе или восстановлено из внешнего хранилища.

### Messages array

Структурированный список сообщений с ролями и содержимым, который передаёт модели нужную историю диалога. В stateless API именно повторная передача messages создаёт эффект многоходового разговора.

### Persistence layer

Внешний слой хранения состояния, переживающий границы model sessions: файлы, Git, БД, memory-файлы, журналы прогресса и другие записи, которые можно загрузить в новый context.

### CLAUDE.md

Markdown-файл Claude Code с устойчивыми инструкциями проекта: архитектурными правилами, командами, соглашениями и workflow. Это внешний persistent context, а не скрытая память модели.

### Auto memory

Механизм Claude Code, при котором Claude сам сохраняет полезные наблюдения и исправления в memory-файлы, чтобы использовать их в будущих сессиях.

### MEMORY.md

Основной индекс Auto memory в Claude Code. В стартовый context автоматически загружаются первые 200 строк или 25 KB, в зависимости от того, какой предел достигнут раньше; подробные тематические файлы читаются по потребности.

### Auto-compaction

Автоматический запуск compaction при приближении conversation к пределу context window. Порог является настройкой продукта, а не фундаментальным свойством LLM.

### Блок точных фактов (Authoritative fact block)

Отдельный структурированный блок с точными ID, суммами, датами, статусами и другими критичными значениями, заново получаемыми из БД/API и добавляемыми в context без генеративного пересказа.

## Retrieval и agentic engineering

### RAG

Retrieval-Augmented Generation: поиск релевантных фрагментов во внешнем источнике и добавление выбранных данных в active context.

### Retrieval

Выбор информации, наиболее релевантной текущему запросу или этапу задачи.

### Tool result

Результат вызова внешнего инструмента, который может быть добавлен в context.

### Subagent

Отдельный агент/вызов с более узкой задачей и собственным context.

### Context engineering

Проектирование того, какие инструкции, history, retrieval results и tool outputs доступны модели на каждом шаге.

### Signal-to-noise ratio

Соотношение полезной информации к нерелевантному или устаревшему контексту.

### Just-in-time context

Стратегия context engineering, при которой агент хранит лёгкие ссылки на данные — пути, идентификаторы, URL, сохранённые запросы — и загружает сами данные через инструменты только тогда, когда они действительно нужны.

## Стоимость и оптимизация

### Input tokens

Токены контекста, которые модель обрабатывает как input.

### Output tokens

Токены, сгенерированные моделью; billed output reasoning-моделей может также включать thinking tokens.

### Prompt caching

Повторное использование большого неизменного prefix для снижения повторных вычислений/стоимости.

### Cache hit

Повторное использование уже закэшированного prefix.

### Batch API

Асинхронная массовая обработка запросов, подходящая для offline workloads.

### Token budget

Планируемый объём input, thinking и output с учётом context limit, стоимости и latency.

## Стохастичность и sampling

### Next Token Prediction
Autoregressive принцип: на каждом decode step модель вычисляет распределение следующего токена, выбирает токен и добавляет его в context.

### Probability distribution
Нормализованные вероятности возможных следующих токенов. Сумма вероятностей равна 1.

### Sampling
Выбор следующего токена из probability distribution с учётом вероятностей кандидатов.

### Stochasticity
Стохастичность — наличие случайности в generation, из-за которой одинаковый prompt может приводить к разным последовательностям токенов и разным ответам.


### Temperature
Устаревший для новых Claude sampling parameter, который менял резкость probability distribution. Последняя Sonnet-модель с поддержкой — **Claude Sonnet 4.6**. В Claude Sonnet 5 non-default значение `temperature` возвращает `400`.

В новых Claude `effort` управляет глубиной reasoning, а prompting — поведением и вариативностью output. `effort` не является прямым эквивалентом temperature.


### top-k
Устаревший для новых Claude sampling filter, ограничивающий candidates K наиболее вероятными токенами. Последняя Sonnet-модель с поддержкой — **Claude Sonnet 4.6**. В Claude Sonnet 5 non-default `top_k` возвращает `400`.


### top-p / nucleus sampling
Устаревший для новых Claude sampling filter по cumulative probability. Последняя Sonnet-модель с поддержкой — **Claude Sonnet 4.6**. В Claude Sonnet 5 non-default `top_p` возвращает `400`.


### Determinism
Способность системы повторять один результат для одинакового input. `T=0` повышает стабильность, но не гарантирует абсолютную идентичность output.

### Structured output
Output с формальным контрактом, например JSON Schema, пригодный для машинной валидации.

### Eval pipeline
Автоматизированная проверка model output через schemas, tests, business rules и другие validators.


## Галлюцинации, привязка к источникам и проверка фактов

### Галлюцинация (Hallucination)

Правдоподобное, но фактически неверное или не подтверждённое утверждение, сгенерированное моделью.

### Привязка к источникам (Grounding)

Привязка ответа модели к конкретным внешним данным: документу, результату поиска, базе данных, результату инструмента или другому источнику истины.

### Отказ от ответа (Abstention)

Осознанный отказ давать конкретный ответ при недостатке данных, например «не знаю» или «данных недостаточно».

### Калибровка (Calibration)

Соответствие заявленной уверенности реальной вероятности быть правым. Хорошо откалиброванная система не должна одинаково уверенно звучать в надёжных и сомнительных случаях.

### Заявленная моделью уверенность (Self-reported confidence)

Оценка уверенности, которую сама модель добавляет к ответу. Полезна для приоритизации проверки, но не является независимым доказательством корректности.

### Фактическая согласованность (Factual consistency)

Насколько ответ модели согласуется с предоставленным источником. Это более узкое понятие, чем общая фактическая истинность ответа о мире.

### Ссылка на источник (Citation)

Структурированная ссылка на конкретный фрагмент источника, который должен поддерживать утверждение.

### Citations API

Механизм Claude API, который привязывает ссылки к реально предоставленным документам и возвращает указатели на конкретные фрагменты источника.

### Детерминированная проверка (Deterministic validation)

Проверка утверждения или действия программным механизмом с однозначным результатом: компилятором, тестами, валидатором схемы, реестром пакетов или запросом к БД/API.

### Несколько независимых запусков (Best-of-N)

Несколько независимых генераций одного задания с последующим сравнением или ранжированием. Расхождения помогают обнаружить нестабильность, но совпадение ответов не доказывает истинность.

### Официальный / первичный источник (Authoritative source)

Источник, который является первичным или официальным для проверяемого факта: реестр пакетов для существования пакета, официальная документация для API, БД для состояния приложения и т. п.
